# B2B-заказы TopEngineer: перенос на хостинг

## Что уже работает

Калькулятор → данные компании → серверный пересчёт → сохранённый заказ → PDF КП, pro forma и необязательного договора → скачивание отдельно или ZIP. Даты не обязательны для подготовки документов. В КП полные программы всех четырёх курсов, дополнительные курсы и цены отделены от заказа. В счёте только заказанные позиции. Платёжный сервис и карта не требуются.

Текущий локальный адрес: http://127.0.0.1:8771/. Кнопка **Get proposal & invoice** под калькулятором. Сервер запущен; после перезагрузки компьютера локальный просмотр запускается файлом `outputs/consulting-course-colours/Start-preview.ps1`.

Режим сейчас: **preview**. Это технически работающий процесс, но реальные платёжные инструкции отключены до проверки реквизитов и налогов. Предварительный номер счёта, предоставленный владельцем, сохранён вне публичного сайта и не попадает в образцы документов или поставку модуля.

## Состав поставки

`topengineer-b2b-module.zip`:

- `training-order/` — самостоятельная форма, API, каталог, генератор документов и Dompdf с зависимостями;
- `integration-reference/` — актуальная HTML-страница и её новые ресурсы как образец для интеграции в текущий Bitrix-шаблон;
- `docs/` — эта инструкция, исследование и вопросы бухгалтерии. **Документы из docs не размещать в публичном каталоге.**

HTML в integration-reference — образец текущего локального сайта. Не заменять им главную страницу рабочего сайта и не перезаписывать шаблоны Bitrix целиком. Оригинальные изображения, Bootstrap, шрифты и Bitrix-ресурсы используются из существующего сайта. Сначала проверить перенос на тестовом поддомене.

## Требования

PHP 8.1+; DOM/XML, mbstring, PDO_SQLite, GD и ZipArchive; HTTPS; возможность задать две переменные окружения и отдельную непубличную папку с записью для пользователя PHP. Рекомендуется актуальная поддерживаемая версия PHP. Рабочие данные на постоянном локальном диске, не во временном каталоге и не внутри public_html. Встроенный PHP-сервер предназначен только для локального просмотра.

## Установка в текущий сайт

1. Разместить модуль, например, в `/consulting/training-order/`. Ссылки формы и адрес API относительные; работать в подпапке они умеют. Вызов из калькулятора использует `new URL('./training-order/', location.href)`.
2. В текущей странице сохранить существующий Bootstrap и стили. Перенести новый блок действий калькулятора и обновлённый `table-calculator.js` из integration-reference. Обязательные элементы: `[data-start-checkout]`, `#checkout-cart-error`, исходные строки `[data-course]`, элементы длительности и участников, данные `#training-rates`. Готовая разметка есть в HTML-образце.
3. В форме `training-order/index.html` подключены локальные исходные CSS и шрифты сайта. На хостинге проверить пути существующих Bitrix CSS; хеши кеша могут отличаться. Логотип берётся из исходного `/local/templates/top_com/assets/img/logo2.png`. Заменять исходные глобальные стили не нужно. Новый `checkout.css` задаёт только расположение блоков; карточки, поля и кнопки используют Bootstrap.
4. Скопировать `settings.example.php` **за пределы webroot**, например в `/srv/topengineer-private/training-orders.php`. Настроить окружение PHP: `TRAINING_ORDER_CONFIG` указывает на этот файл, `TRAINING_ORDER_DATA_DIR` — на `/srv/topengineer-private/order-data`. Фактические пути задаёт хостинг.
5. В приватном конфиге указать точные разрешённые HTTPS-origin сайта без путей в `allowed_origins`. Для локального просмотра уже разрешены 127.0.0.1:8771 и localhost:8771. Лишние origins в рабочей установке удалить.
6. Убедиться, что авторизация документов доходит до PHP: заголовок `Authorization` используется для скачивания. Для Nginx/FastCGI при необходимости передавать `fastcgi_param HTTP_AUTHORIZATION $http_authorization;`. Не включать стороннюю аналитику, CRM или рекламные скрипты на странице с реквизитами клиента.

## Защита служебных файлов

Для Apache 2.4 в модуле уже есть `.htaccess`: запрещены src, vendor, data, файл примера настроек и текст договора; отключён листинг. Хостинг должен разрешать соответствующие `.htaccess` и директивы. Если `Options -Indexes` запрещён хостингом, листинг отключает администратор в конфигурации сервера, а строку удаляют из .htaccess.

В Nginx `.htaccess` не применяется. Добавить правила запрета для фактического пути модуля, например:

```nginx
location ~ ^/consulting/training-order/(src|vendor|data)(/|$) { return 404; }
location = /consulting/training-order/settings.example.php { return 404; }
location = /consulting/training-order/agreement-clauses.json { return 404; }
```

После установки проверить, что эти адреса возвращают 403/404, а не содержимое. API и форма должны работать по HTTPS. Настроить Secure-cookie с корректной передачей HTTPS от обратного прокси; не доверять произвольному клиентскому заголовку о протоколе. Каталог БД и банковский конфиг не должны иметь публичного URL.

## Переход к рабочей оплате

До ответов бухгалтерии оставить `mode = preview`.

После согласования заполнить в **приватном** конфиге:

- `seller`: утверждённые юридические данные; затем `details_confirmed = true`;
- `bank`: точный получатель, IBAN, SWIFT/BIC, банк, адрес, корреспондент при необходимости, EUR; затем `details_confirmed = true`. Указанного национального счёта недостаточно для международной инструкции. Номер IBAN не вычислять самостоятельно;
- `tax_rules`: только утверждённые правила. `outside_scope` и `exempt` — разные основания; `exclusive` добавляет налог к цене, `inclusive` выделяет его из цены. `rate_bps = 2000` означает 20%, **это пример синтаксиса, не установленная для TopEngineer ставка**. `note` — согласованный текст основания/режима на английском. Для каждого правила нужен `approved = true`;
- `foreign_business` — общее правило для зарубежных компаний, только если бухгалтер действительно подтвердит его применимость ко всем таким заказам. Иначе задавать отдельные коды ISO страны и не утверждать широкое правило. Если для одной страны правила различаются по статусу клиента или типу услуги, не включать для неё автоматическую оплату, пока не будет добавлен соответствующий критерий;
- условия оплаты, окончательные условия отмены, переносов, возвратов и договор. `agreement-clauses.json` — текущий черновик. Сначала заменить и проверить его текст, пересобрать каталог, затем изменять `agreement_approved`. В текущем шаблоне явно оставлены положения для дальнейшего согласования;
- `mode = live` включать после проверки настройки на тестовом заказе. Режим live сам по себе не обходит проверку банка, данных поставщика или налогового правила страны.

Проверка IBAN/BIC проверяет структуру и контрольную сумму IBAN, но не доказывает принадлежность счёта компании. Это сверяется с официальной банковской инструкцией.

**Ограничение этого релиза:** это оформление заказа и платёжный запрос. SEF, окончательная налоговая фактура, автоматическая банковская сверка, автоматическая отправка email и электронная подпись не подключены. После прихода денег бухгалтерия действует по утверждённому процессу. Статус заказа остаётся `awaiting_bank_transfer`; скачивание файла не означает оплату.

## Данные и обслуживание

База `orders.sqlite` хранит неизменяемый состав заказа, цены, программы и реквизиты на момент его создания. Новые цены не должны переписывать старые заказы. Номера pro forma последовательны по годам; предварительная серия отделена от рабочей. Повтор одного и того же запроса возвращает тот же заказ.

Скачивание доступно по случайному токену в HTTP-заголовке, а не по угадываемому номеру счёта. Токены и файлы клиентов не публиковать. Последний заказ можно открыть повторно в той же сессии браузера. После закрытия сессии клиент сохраняет скачанные PDF/ZIP; публичного поиска по email нет.

Хранить резервные копии БД согласованным способом SQLite Backup API либо на короткой остановке записи; при WAL нельзя полагаться на простое копирование одного файла открытой базы. Не переносить тестовую БД в рабочую установку. Определить ответственного за сверку поступлений, бухгалтерские документы, срок хранения данных, права доступа и политику обработки персональных данных.

Программы и цены синхронизируются сборкой `work/consulting-course-colours/build_parallel.py`. Каталог модуля: `training-order/data/catalogue.json`. Если обновлять условия договора, каталог тоже нужно пересобрать. PDF получает шрифты локально; внешние сайты и JavaScript при рендеринге отключены.

## Проверки, выполненные локально

- 60 сочетаний длительности и количества участников, минимальная оплата за 3 человека для 5/10 дней, сервер игнорирует переданную клиентом цену;
- смешанный заказ 450 + 1750 + 3500 = 5700 EUR; даты через конец месяца и года включительно;
- обязательные B2B-реквизиты, предварительное прохождение Level 1 для заказа только продвинутых курсов, неподходящие значения и устаревшая цена;
- повторная заявка, CSRF, посторонний origin, защита файлов и скачивание документов;
- отдельная непубличная синтетическая проверка режима live: IBAN/BIC, налог внутри/сверху цены, округление центов, блокировка страны без утверждённого правила;
- PDF: все 352 пункта в КП, обычный счёт на одной странице, договор на двух, программы по частям без почти пустых хвостов; весь пакет скачивается из браузера;
- форма и результат на ширинах 320, 390, 768 и 1920 px: без горизонтального переполнения. Возврат в калькулятор сохраняет курсы, длительности, число участников и даты.
